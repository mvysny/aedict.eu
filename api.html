Detecting Aedict

An app targeting Android 11 (API 30) or newer sees Aedict only if its AndroidManifest.xml asks for it, see package visibility:

<queries>
    <package android:name="sk.baka.aedict3" />
</queries>

Without it the check below always answers false, and the Service API can't connect. Starting Aedict's activities works either way.

public static boolean isAedictPresent(Context context) {
    final Intent intent = new Intent("sk.baka.aedict3.action.ACTION_SEARCH_JMDICT");
    return !context.getPackageManager().queryIntentActivities(intent, PackageManager.MATCH_DEFAULT_ONLY).isEmpty();
}

Searching for a string in Aedict

From Anywhere (since Aedict 3.50.11)

You can simply embed the following links into your html page, into your AnkiDroid card, or into your Android application:

  • aedict://はは - use the <a href="aedict://はは">はは</a> HTML code to add such a link to your HTML code or AnkiDroid card
  • aedict://はは%20は
  • aedict://a?q=はは%20
  • http://aedict?q=はは - for certain sites that would reject to render any links not starting with http:// or https://. Android 12 and newer open such a link in the browser instead of Aedict, so prefer the aedict:// links wherever they work.

Note that you need to escape spaces with %20. Some browsers will escape Japanese characters for you, some will not. You may need to escape the characters yourself, see the URL Encode Decode page for more details.

In Aedict Online

To open a search in Aedict Online, the web edition of Aedict, link to https://aedict-online.eu/search?query=はは, escaping the word as above. Older links of the form https://aedict-online.eu/#!/はは keep working.

From Your Android App

To query Aedict without showing its UI, use the Service API (since Aedict 3.30) or the no UI search (since Aedict 3.56.0).

To display the Search Activity in Aedict, start the "sk.baka.aedict3.action.ACTION_SEARCH_JMDICT" intent with the following extras:

Intent ExtraSinceTypeMeaning
kanjis2.0StringRequired: what to search for. Aedict 3.x accepts anything: kanji, hiragana, katakana, romaji, english, french, etc. Aedict 3.x also automatically deinflects words. See other parameters for details.
deinflect3.2BooleanDefaults to true. If set to false, no verb deinflection is performed.
match_jp3.2StringDefaults to StartsWith. May have the following values: Exact - exact match; StartsWith - matches any JMDict entry starting with given term; EndsWith - matches any JMDict entry ending with given term; Substring - matches any JMDict entry which contains given term. Any other value is an error.
match_sense3.2StringDefaults to Exact. Defines how the term is matched to the sense (english, french, dutch, etc) part of the JMDict entry. May have the following values: Exact - exact word match, e.g. "auto" will match "auto mechanic" but not "automechanic"; StartsWith - "car" will match "crane carrier" but not "ecar"; EndsWith and Substring are unsupported because of Lucene limitations. Any other value is an error.
analysis_fallback3.2BooleanDefaults to true. If true, Aedict will try to analyze given japanese sentence present in the "kanjis" field if JMDict search returns no results. If false, analysis is not performed and Aedict simply displays "No Results"
search_in_examples3.2BooleanDefaults to false. If false, JMDict search is performed. If true, Tatoeba example sentence search is performed.
search_in_kanjidic3.4.35BooleanDefaults to false. If false, JMDict search is performed. If true, Kanjidic2 search is performed.
return_results3.4.9BooleanDefaults to false. If false, results are simply shown in Aedict as a list. If true, Aedict returns the results instead of showing them: start the intent for a result, see the example below. The result intent's serializable extra "result" is an ArrayList<HashMap<String, String>>, one map per entry, mapping a variable name (without the percent signs) to its value. The variables are those of the Custom Export Format, all but %examples% and %words%. See also issue #243.
return_user_selected_result3.4.35BooleanDefaults to false. If true and the user taps an entry, Aedict returns that entry: the result intent has a String extra per Custom Export Format variable, named without the percent signs, all but %examples%.
prolong_vowels3.4.31BooleanDefaults to false. If true, searching e.g. for shojiki will also find shoujiki
jlpt3.4.31ByteMissing by default; 1..5, corresponds to JLPT N1..N5 levels, N5 being the easiest one. If specified, result words or kanji must belong to the JLPT level specified. Pass a byte, (byte) 3: Aedict before 3.56.0 ignores an int.
commonOnly3.4.31BooleanDefaults to false. If true, only common words (P) are returned
showEntryDetailOnSingleResult3.7BooleanDefaults to false. If true and the search produces only one entry, that one entry's details is shown immediately. However, if return_results is set to true then this is ignored
maxResults3.32IntegerDefaults to 200 for JMDict search, 100 for example sentence search. Maximum number of results to return.
disable_globbing3.39.12BooleanDefaults to false. If true, * and ? characters are treated as other delimiters and ignored.

The JMDict search takes every extra. The example sentence search takes only match_jp, match_sense and maxResults; the Kanjidic2 search only match_jp, match_sense and jlpt.

Example:

final Intent intent = new Intent("sk.baka.aedict3.action.ACTION_SEARCH_JMDICT");
intent.putExtra("kanjis", "saseru");
intent.putExtra("deinflect", false);
intent.putExtra("match_jp", "Exact");
intent.putExtra("jlpt", (byte) 3);
startActivity(intent);

With return_results, the results come back to your activity:

private final ActivityResultLauncher<Intent> search = registerForActivityResult(
        new ActivityResultContracts.StartActivityForResult(), result -> {
            if (result.getResultCode() == Activity.RESULT_OK) {
                final List<Map<String, String>> entries =
                        (List<Map<String, String>>) result.getData().getSerializableExtra("result");
                // entries.get(0).get("kanji"), .get("reading"), .get("sense")...
            }
        });

void searchFor(String word) {
    final Intent intent = new Intent("sk.baka.aedict3.action.ACTION_SEARCH_JMDICT");
    intent.putExtra("kanjis", word);
    intent.putExtra("return_results", true);
    search.launch(intent);
}

Searching for a string in Aedict, no UI

If you wish to use return_results but you do not like Aedict showing you UI, please use "sk.baka.aedict3.action.ACTION_SEARCH_JMDICT_NOUI" action instead. You can use all of the parameters mentioned above; however the return_results parameter will be ignored and will always be true. Launch it as in the return_results example above.

It works since Aedict 3.56.0. Older Aedicts accept the intent but crash instead of answering, and your activity gets no result: for them, use the Service API. With the <queries> element from Detecting Aedict, the version tells which one to use:

static boolean isNoUiSearchWorking(Context context) throws PackageManager.NameNotFoundException {
    final PackageInfo aedict = context.getPackageManager().getPackageInfo("sk.baka.aedict3", 0);
    return PackageInfoCompat.getLongVersionCode(aedict) >= 35600;  // 3.56.0
}

Aedict runs one search at a time, shared with the Service API: a newer no UI search, searchJmdict or analyze cancels a no UI search still running, whose caller then gets RESULT_CANCELED. Until Aedict's dictionaries are downloaded, the result is a single entry whose reading asks the user to start Aedict and download them.

Kanji search activities

Since Aedict 3.5, you can start the following action to search for a kanji (all data entered by the user):

  • sk.baka.aedict3.action.ACTION_SEARCH_UNITED

When the user taps a kanji, the activity terminates and returns the kanji in the "kanji" extra:

private final ActivityResultLauncher<Intent> pickKanji = registerForActivityResult(
        new ActivityResultContracts.StartActivityForResult(), result -> {
            if (result.getResultCode() == Activity.RESULT_OK) {
                final String kanji = result.getData().getStringExtra("kanji");
                // do something with the kanji
            }
        });

pickKanji.launch(new Intent("sk.baka.aedict3.action.ACTION_SEARCH_UNITED"));

Programmatic Kanji search

Since Aedict 3.4.35, you can send the "sk.baka.aedict3.action.ACTION_SEARCH_KANJIDIC2" intent to search by kanji parts or the SKIP code. Aedict shows the matching kanji, and returns the one the user taps in the "kanji" extra, as above. The following table summarizes the intent parameters; one of them is required:

Intent ExtraSinceTypeMeaning
parts3.4.35StringAll parts the kanji must contain. Note that if a non-part character is present, the search returns zero results
skip3.4.35StringIgnored if the parts extra is present. The SKIP code, in the format of 4-1-4

Example, with the pickKanji launcher from above:

final Intent intent = new Intent("sk.baka.aedict3.action.ACTION_SEARCH_KANJIDIC2");
intent.putExtra("parts", "豆頁");
pickKanji.launch(intent);  // the user taps 頭, the "kanji" extra is 頭

Resolve Kanjis

Since Aedict 3.7, the "sk.baka.aedict3.action.ACTION_RESOLVE_KANJIDIC2" intent answers at once, with no UI shown on Aedict's side:

private final ActivityResultLauncher<Intent> resolve = registerForActivityResult(
        new ActivityResultContracts.StartActivityForResult(), result -> {
            if (result.getResultCode() == Activity.RESULT_OK) {
                final List<Map<String, String>> entries =
                        (List<Map<String, String>>) result.getData().getSerializableExtra("result");
                final String readingOf豆 = entries.get(0).get("reading");
            }
        });

final Intent intent = new Intent("sk.baka.aedict3.action.ACTION_RESOLVE_KANJIDIC2");
intent.putExtra("kanji", "豆頭");
resolve.launch(intent);

The result intent's serializable extra "result" is an ArrayList<HashMap<String, String>>, one map per kanji, non-kanji characters ignored. Each map maps a variable name (without the percent signs) to its value; for a list of variables, please see Custom Export Format.

Until Aedict's dictionaries are downloaded, the result is a single entry whose reading asks the user to start Aedict and download them; Aedict before 3.56.0 crashes instead, and your activity gets no result.

Since Aedict 3.31: To resolve given kanji set and show the result on-screen, in Aedict's activity:

final Intent intent = new Intent("sk.baka.aedict3.action.ACTION_RESOLVE_KANJIS");
intent.putExtra("kanjis", "豆頭");
startActivity(intent);

This will show a list with two kanjis, 豆 and 頭.

Service API

Since Aedict 3.30, an app can query Aedict through its bound service instead of launching intents: Aedict stays hidden in the background. The client is sk.baka.aedict.remote.AedictClient from the jputils library, on Maven Central:

implementation("com.gitlab.mvysny.jputils:jputils:4.0")

jputils is GPL 3.0 licensed. Your manifest also needs the <queries> element from Detecting Aedict. Create the client in your activity's onStart() and destroy it in onStop(). Call it from the main thread; the replies arrive there too:

public class MyActivity extends AppCompatActivity implements AedictClient.Listener {
    private AedictClient aedict;

    @Override
    protected void onStart() {
        super.onStart();
        try {
            aedict = new AedictClient(this, this);
        } catch (RemoteException e) {
            Log.w("MyActivity", "Aedict is not installed, or the manifest lacks the <queries> element", e);
        }
    }

    @Override
    protected void onStop() {
        if (aedict != null) {
            aedict.destroy();
            aedict = null;
        }
        super.onStop();
    }

    void lookUp(String word) throws RemoteException {
        final Bundle args = new Bundle();
        args.putBoolean("commonOnly", true);
        aedict.searchJmdict(word, args, 1);
    }

    @Override
    public void onResult(int id, List<Map<String, String>> entries) {
        // the reply to request 1: entries.get(0).get("kanji"), .get("reading"), .get("sense")...
    }

    @Override
    public void onKanjis(String kanjis) {
        // the kanji matching a drawing, best match first
    }
}

The client's requests:

MethodDoesReplies to
searchJmdict(kanjis, otherArgs, id)Searches like ACTION_SEARCH_JMDICT; otherArgs takes its extras, all but return_results, return_user_selected_result and showEntryDetailOnSingleResult.onResult(id, entries)
resolveKanjis(kanji, id)Like ACTION_RESOLVE_KANJIDIC2: one entry per kanji in kanji, other characters ignored.onResult(id, entries)
analyze(sentence, id)Splits a Japanese sentence into words, as the search's analysis fallback does. The first entry is the whole sentence, its furigana the sentence with readings.onResult(id, entries)
analyzeKanjipad(coords, forceFuzzy1Out, forceFuzzy2Out)Recognizes a drawn kanji. coords holds 4 numbers per stroke: start x, start y, end x, end y, in any unit, y pointing down. With either flag true, kanji with up to two strokes more or fewer match too.onKanjis(kanjis)

The entries are maps as in return_results above. A request sent before the service connects waits, and goes out once it does. Aedict runs one search at a time: a new searchJmdict, analyze or no UI search cancels the one still running, which then gets no reply, and the id tells which request a reply answers; a new drawing likewise cancels the previous one. Until Aedict's dictionaries are downloaded, every request but a drawing gets a single entry whose reading asks the user to start Aedict and download them.
